// FINAL PROJECT — IoT Network Protocol

Wi-Fi / LoRa
하이브리드 프로토콜

다중 로봇 환경에서 Wi-Fi와 LoRa를 RSSI 기반 FSM으로 자동 전환하는 하이브리드 통신 프로토콜 설계 및 구현 방안

팀 구성 2~3인
발표 16주차 수요일
분류 IoT / Network
// 01

프로젝트 개요

다중 로봇이 운용되는 환경에서 Wi-Fi 커버리지가 불안정한 구간이 발생할 때, 통신 단절 없이 LoRa로 자동 전환하고 복귀하는 하이브리드 프로토콜을 설계한다.

핵심은 프로토콜 전환의 투명성이다. 관제 서버는 로봇이 어떤 프로토콜을 쓰는지 관계없이 동일한 토픽 구조로 데이터를 수신한다.

핵심 목표

① 전환 순간 데이터 손실 최소화

버퍼링 + WARNING 구간 이중 채널로 전환 순간 패킷 손실 방지

② Ping-pong 현상 방지

안정화 조건(일정 시간 RSSI 유지)을 만족해야만 채널 전환 확정

③ 관제 투명성

Protocol Adapter로 정규화 — 관제 코드는 프로토콜 변경 없이 동작

서버 내부 프로세스 분리

두 프로세스가 Mosquitto를 경계로 깔끔하게 분리된다. 언어 경계가 프로세스 내부가 아니라 Mosquitto 브로커에서 나뉘므로 각 프로세스를 독립적으로 재시작 가능하다.

[ C 브리지 프로세스 ] [ Python 프로세스 ] UART 수신 (서버 TTGO) paho-mqtt subscribe robot/+/status └─ robot_id 파싱 └─ dedup (robot_id + seq, 200ms) └─ 토픽 구성 └─ WebSocket broadcast └─ libmosquitto publish └─ 관제 브라우저 └─▶ Mosquitto (localhost) ◀─┘

FSM 상태 머신 (로봇 RPi)

로봇 RPi에서 C로 구현되는 핵심 로직. RSSI를 주기적으로 샘플링하여 3개 상태 간 전환을 결정한다.

🟢 NORMAL
  • Wi-Fi로 데이터 송수신 (libmosquitto publish)
  • LoRa (TTGO) Sleep 상태 유지
  • RSSI > T1 조건 유지 (예: −65 dBm)
  • 버퍼 비움 확인
T2 < RSSI ≤ T1 → WARNING 진입
↕ 안정화 조건 충족 시 복귀
⚠️ WARNING (핑퐁 방지 구간)
  • Wi-Fi 살아있으면 → Wi-Fi로 전송, LoRa 대기 (전송 안 함)
  • Wi-Fi 끊기면 → LoRa로 전송, Wi-Fi 재연결 시도 계속
  • Wi-Fi 재연결 성공해도 → 안정화 조건 충족 전까지 대기
  • 안정화 조건: N초 동안 RSSI 샘플 M개 중 K개 이상 T1 이상
  • 초기값 예시: 10초 / 20샘플 / 15개 이상 / −65 dBm (실측 조정)
  • 이 구간에서 Wi-Fi + LoRa 중복 수신 가능 → 서버 dedup 처리
RSSI < T2 OR 완전 끊김 → LORA ONLY
↕ Wi-Fi 비콘 감지 + Handshake 완료 시 복귀
📡 LORA ONLY
  • LoRa로만 데이터 전송
  • Wi-Fi 모듈 비활성 (전력 절감)
  • 백그라운드에서 Wi-Fi 비콘 주기적 스캔
  • 비콘 감지 → 재연결 시도 → Handshake 완료 → WARNING 복귀

버퍼링

전환 순간 전송하지 못한 패킷을 메모리 큐에 보관한다. 새 채널 연결 확정 후 seq 번호 순서대로 flush한다. seq 번호가 있으므로 서버에서 순서 복원 및 손실 감지가 가능하다.

임계값 (T1, T2)

파라미터초기 예시값비고
T1 (NORMAL ↔ WARNING)−65 dBm실측 필수
T2 (WARNING → LORA)−80 dBm실측 필수
안정화 시간10초실측 조정
안정화 샘플 수20개 중 15개실측 조정
RSSI 샘플링 주기500ms조정 가능

※ 모든 임계값은 관제 대시보드에서 원격 수정 가능하도록 설계됨

// 04

페이로드 포맷

LoRa Time on Air 단축을 위해 바이너리 구조체를 사용한다. JSON 대비 전송 시간이 대폭 줄어 CSMA/CA 채널 점유 시간도 감소한다.

robot_iduint8 / 1B
sequint16 / 2B
tsuint32 / 4B
stateuint8 / 1B
rssiint8 / 1B
tempint16 / 2B
필드타입크기예시값용도
robot_iduint81 byte0x01로봇 식별 / MQTT 토픽 구성
sequint162 byte0x002A (42)dedup / 손실 감지 / 순서 복원
tsuint324 byteUnix timestamp발신 시각 기준 정렬
stateuint81 byte0=N / 1=W / 2=LFSM 현재 상태
rssiint81 byte−72Wi-Fi RSSI (관제 모니터링)
tempint162 byte2350 = 23.50°C온도값 (×100 정수 인코딩)
총 헤더 고정 11 byte — LoRa 255 byte 한도 내 충분히 여유

temp는 RPi CPU 온도(/sys/class/thermal/thermal_zone0/temp)를 읽으면 별도 센서 없이 즉시 사용 가능하다.

Wi-Fi 경로는 프로토타입 단계에서 JSON 사용 가능. LoRa 경로는 처음부터 바이너리 구조체 권장.

CSMA/CA (다중 로봇 충돌 회피)

여러 로봇이 동시에 LoRa로 전환할 때 채널 충돌을 방지한다. sandeepmistry 라이브러리의 CAD(Channel Activity Detection) 기능이 하드웨어 레벨에서 지원된다.

// TTGO Arduino — CSMA/CA 흐름 LoRa.onCadDone(onCadDone); LoRa.channelActivityDetection(); void onCadDone(boolean signalDetected) { if (signalDetected) { // 채널 사용 중 → 랜덤 백오프 후 재시도 delay(random(10, 50)); // robot_id 기반 시드 권장 LoRa.channelActivityDetection(); } else { // 채널 비어있음 → 전송 sendPacket(); } }

DIO0 핀(TTGO 기준 핀 26)이 인터럽트 가능 핀이므로 별도 하드웨어 수정 없이 바로 사용 가능하다.

TDMA vs CSMA/CA 비교

TDMACSMA/CA ✓ 채택
방식시간 슬롯 고정 배분채널 비어있으면 전송
로봇 간 동기화필요 (구현 복잡)불필요
구현 난이도높음낮음
적합 상황다수 로봇, 주기적 전송소수 로봇, 비정기 전환

udev rule — 시리얼 포트 고정

TTGO 두 개(로봇용, 서버용)의 USB 포트 번호가 재부팅 시 바뀌는 문제를 방지한다.

# /etc/udev/rules.d/99-lora.rules # 로봇 RPi 쪽 SUBSYSTEM=="tty", ATTRS{idVendor}=="10c4", ATTRS{serial}=="ABC123", SYMLINK+="lora_robot" # 서버 PC 쪽 SUBSYSTEM=="tty", ATTRS{idVendor}=="10c4", ATTRS{serial}=="XYZ789", SYMLINK+="lora_server" # 적용 sudo udevadm control --reload-rules

이후 코드에서 /dev/lora_robot, /dev/lora_server로 고정 참조 가능하다.

TTGO 펌웨어 설계

로봇용 TTGO (송신 브리지)

단계동작
① UART 수신RPi로부터 바이너리 패킷 수신 (\n 구분)
② CADLoRa.channelActivityDetection() 호출
③ 전송 또는 백오프채널 비어있으면 전송, 사용 중이면 랜덤 백오프 후 재시도
④ TxDone 콜백전송 완료 후 다음 패킷 대기

서버용 TTGO (수신 전용)

단계동작
① 수신 대기LoRa.receive() — 연속 수신 모드
② 패킷 수신onReceive 콜백 — RSSI, SNR 함께 기록
③ UART 송출바이너리 + RSSI/SNR → 서버 C 브리지로 전달
④ 송신 없음송신 관련 코드 일절 없음 (채널 오염 방지)

LoRa 파라미터: 915E6, TxPower 20, SyncWord 팀 전용값, CRC 활성화 권장

실측 필요 항목

시스템 구현 후 실측으로 도출해야 하는 수치들. 관제 대시보드에서 원격 수정 가능하도록 설계되어 있으므로 코드 재배포 없이 튜닝 가능하다.

항목초기값측정 방법
